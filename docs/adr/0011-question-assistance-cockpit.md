# ADR 0011: Question assistance workbench

## Status
Accepted, 27 October 2026. Required implemented decisions have M04–M10 acceptance evidence. Optional native translucency uses the documented opaque fallback in ADR 0021. Acceptance does not assert semantic accuracy or unavailable speech-aligned latency/cost metrics.

## Context
On 23 October 2026 the user requested a UX design and implementation prompt, dark translucent styling, one-press assistance and FULL AUTO. They then rejected the initial oversized answer pane and assumptions that AI would reliably organize a flood of speech into questions. Their revised layout requests two answer columns, one transcript column and one question column.

The bootstrap's manual text-selection path, Python/Electron, local audio/STT and Gateway constraints remain. The current server's global query task, broadcasts and absent protocol negotiation/ownership need work before AUTO.

## Decision
Use a four-column workbench with an independent raw transcript, fallible overlapping question hypotheses, persistent working answer cards and kept/previous cards. The primary no-selection action snapshots recent raw TIME context directly; question detection is optional. Show original words separately from inferred/human-set intent. Provide quick source inspection, manual creation, edit/split/merge, dismiss/undo and wrong-question correction. Every answer is an unreviewed draft; pinning or source linkage does not verify it.

Use backend-owned bounded detection/scheduling, one answer job and newest pending automatic candidate while retaining the inspectable candidate inbox. Human correction/selection prevents automatic interference. New answers add immutable cards instead of replacing pinned/read content. This revision supersedes the earlier proposal's 70/30 layout and timed eight-second replacement/countdown; version history retains that design.

Require request/answer/snapshot/candidate revision/session identity, single controlling UI ownership, scoped completion/errors, protocol v2 capability migration and legacy manual compatibility. Start with bounded ephemeral source/question/answer working sets and explicit limits; persist layout/profile/source preferences, not armed AUTO or transcripts by surprise.

Preserve the original separate SettingsPage and all existing Desk/RAG/docs/model/benchmark/image features and stored data. A dedicated audio overlay relocates source controls while a selected-input level bar remains in the main header. Opening preferences must not alter capture/query lifecycle; real telemetry reuses the existing audio_level contract.

Use a working opaque Desk baseline, with optional supported native translucency verified against the installed Electron build and actual Ubuntu compositor. Text/cards remain opaque. Implementation evolved through protocols v2–v6; the SQLite document schema and local capture/STT boundary remain unchanged.

## Alternatives considered
- The original 70/30 answer pane: large reading anchor, poor transcript space and density; rejected by the user.
- Detector-gated manual answering: convenient when correct, blocks assistance on false negatives and disguises wrong intent; direct raw-context path remains independent.
- Treating eligible candidates as verified questions: valid source ranges cannot prove meaning or answer accuracy; keep hypotheses/drafts correctable.
- Timer-driven answer replacement: bounded reading time but loses a useful surface; persistent cards plus pinning provide continuity.
- Two simultaneous model answers per request: extra latency/cost without resolving truth; two UI columns instead preserve working and kept/previous material.
- Frontend-only AUTO on each partial: duplicate/cancellation/cost and ownership risk; use backend lifecycle.
- Whole-window opacity: hurts text contrast and has Linux limitations; background alpha plus native fallback.

## Consequences
This requires orchestration/protocol work as well as layout. Detection/generation can fail semantically even when IDs/ranges validate. Measure real latency, false positives/negatives, recovery effort and call counts with messy speech; do not claim infallibility from a polished demo. Retain raw-context access during detector outages. Native features need device/compositor acceptance. Implementation and required functional acceptance are recorded below; semantic quality remains a measured limitation.

See [specification](../design/live-helper-cockpit.md), [implementation prompt](../prompts/live-helper-cockpit-implementation.md), [design index](../design/INDEX.md) and current [API](../API.md).

## Authorized bootstrap extension

The [bootstrap](../prompts/bootstrap.md) scope (local audio/STT, Gateway language/embeddings, manual text selection and run-on-selection) is extended by this work to include optional question detection and FULL AUTO drafting. The extension is additive: raw-context answering must remain available when detection is disabled, failing, or empty, and no automatic answer is spoken, sent, or injected into another application.

## Implementation contracts (C01-C06)

These contracts originated in the [execution plan](../plans/live-helper-cockpit-execution-plan.md). They are accepted through the implementation/evidence mapping below. C03 records the original v2 design; the current [API](../API.md) and ADRs 0014/0016/0018/0019 define the implemented v3–v6 payloads. Original command names and rollout instructions here are design history, not an additional wire API.

- **C01 — Separate raw evidence, intent, execution, and display.** Raw finalized text stays exactly as accepted by the existing STT/store pipeline (no semantic cleanup or question grouping). Keep the existing near-duplicate STT suppression; detector deduplication is separate. A snapshot owns copies of text and source metadata, so later transcript changes cannot modify it. Candidate wording and human-edited wording are separate from the raw excerpt. One generation creates one answer card; working and kept columns are display locations, not parallel model jobs. Keep candidate workflow, generation status, unreviewed label, placement, and supersession metadata separate; pinning does not imply correctness. Snapshots/cards stay ephemeral initially; existing persistent preferences, benchmark data, and RAG SQLite storage are preserved.
- **C02 — Identity and source offsets.** Introduce `backendInstanceId`, `connectionId`, `sessionEpoch`, `audioEpoch`, `segmentKey` (composite of `audioEpoch` + original segment ID), `transcriptRevision`, `snapshotId`, `candidateId`/`candidateRevision`, `requestId`/`answerId`, `commandId`, and `eventSeq`. Use half-open character offsets `[start, end)` in Unicode code points (Python slicing convention); convert browser UTF-16 DOM offsets explicitly. Every source span carries `segmentKey`, revision, offsets, `t0`, `t1`, source kind, source name, and `audioEpoch`; ranges validate against actual stored text. Source kind identifies an input, not a person. The no-target action freezes a window ending at the last finalized anchor visible at the press; it must not include newer text received before processing the command. Use complete intersecting finalized segments because word-level timing is unavailable; report the actual included range.
- **C03 — Proposed v2 command/event surface.** Keep the top-level `type` envelope and add `protocolVersion: 2` to v2 traffic, preserving legacy manual envelopes through an adapter. Add `hello`/`claim_control`, `hello_ack`/`control_state`, `get_command_status`/`command_status`, `create_snapshot`, `run_context_query`, `run_snapshot_query`, `cancel_answer`, `candidate_action`, `answer_action`, `context_note_action`, `set_detection`, `set_auto`, `interaction_state`, plus server events `command_ack`, `snapshot_created`, `candidate_update`, `detector_state`, `assistance_state`, `answer_accepted`, `answer_chunk`, `answer_finished`, `request_error`. Answer statuses are `completed`, `cancelled`, `failed`, `empty`, and `superseded`. Use stable error codes for offline/not-ready, incompatible version, not-owner, stale-epoch, stale-revision, invalid-span, capacity, and dependency failures. Advertise only implemented capabilities; do not advertise `full_auto` before M08 passes. A nonterminal legacy `query_state` cannot discard the request record before `query_response` arrives.
- **C04 — Ownership, disconnected sends, and legacy compatibility.** The first successful v2 claimant becomes controller; other connections are read-only for assistance and capture-changing commands. Owner disconnect cancels owned jobs, invalidates pending detection, releases control, and pauses AUTO. A second window claims released control explicitly; no silent transfer or auto-arming. Reconnect re-negotiates; retained client cards become historical records and stale events cannot mutate new jobs. Legacy manual clients remain usable when no v2 controller holds the lease, serialized through the same answer slot; a legacy client cannot cancel another connection's job. Shared transcript/audio/status may stay broadcast; request chunks, completions, and errors use targeted replies. `WSClient.send` returns a typed success/rejection result and never queues paid commands for replay after reconnect. Use a five-second send-acknowledgement deadline; on expiry show an unknown-acceptance state and reconcile by `commandId` without automatic resend. Retain command outcomes in the connection's bounded request history; a duplicate `commandId` returns the prior outcome without another paid call.
- **C05 — Profiles, targets, attachments, and reruns.** An explicit target wins over the recent-context window; clearing it restores recent-context behavior. Consume a target only after positive request acceptance; keep it after offline/validation/capacity rejection. Visible modes are `Preset` and `Custom`; in Preset mode send its instruction and no hidden custom override. In Custom mode show the effective instruction and disable submission for an empty custom instruction. On initial migration, expose a nonempty stored custom instruction as an active visible Custom mode while preserving the saved preset. Retain all four existing presets and explicit Run preset / Run custom actions. Preserve original source selection and its editable draft separately; reset restores source wording and never rewrites raw text. Freeze effective instruction, model, source context, human notes, and explicit image attachment at acceptance. Rerun uses the frozen generation inputs, a new request/answer identity, and the original retrieval context. Never capture a screenshot from a detector/AUTO loop. Human notes have explicit include-in-future-context controls defaulting OFF; freeze included note IDs, versions, and text separately from evidence.
- **C06 — Initial bounds and failure policy.** Named defaults (subject to evidence-based adjustment with an ADR): recent-context choices 20/45/90 s (default 20); detector lookback latest 90 s of finalized text from the current audio epoch; detector debounce 1.0 s (configurable 0.8-1.2 s); detector concurrency one active call plus one latest-revision dirty flag; detector output at most eight proposals, 1,500 output tokens, 15 s timeout; detector context at most 12,000 characters with a visible truncation notice; minimum two seconds between detection starts and no automatic retry of an unchanged failed revision; generation concurrency one active answer plus one newest pending AUTO candidate; candidate working set 200 revisions/records; working answers 50 cards; kept answers and human notes 50 items (reject additional keeps visibly); unattached pinned moments 50 snapshots; source snapshot size 24,000 characters (reject oversized manual input visibly). Snapshots are owned by live candidates/targets/moments/cards and released when their last reference is removed. Capacity never silently removes active, selected, edited, inspected, pending, or pinned material. Keep Gateway provider fallback and add no unbounded outer retry loop. Detector failures, no candidates, retrieval failures, empty answers, and cancelled answers are distinct states.

## Frontend test-tool choice (M00)

Deterministic frontend tests use Vitest + jsdom + React Testing Library + user-event (`npm run test`, `npm run test:watch`). Configuration is local (`frontend/vitest.config.ts`) and test-only helpers/fixtures live under `frontend/src/cockpit/__tests__/`. The production build still uses `vite.config.ts`; the backend keeps Python `unittest`. This does not upgrade the application stack and performs no live backend, audio, RAG, or paid calls.
